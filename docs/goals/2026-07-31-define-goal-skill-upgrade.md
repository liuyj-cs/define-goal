## 目标陈述

在本仓库（define-goal skill 的源码仓库）落地目标所有者已逐条确认的 8 项设计改进：验收/结项模式、代拍的板、"路可换、货不少"、反向验证、开工回执、写作纪律、相关目标小节、待裁决清单；同步升级 `define-goal/scripts/validate_goal.py`（状态生命周期、两处已复现误报修复），补最小回归测试与仓库卫生。完成后：skill 仍以 `/define-goal` 定义目标、以宿主内置 `/goal` 执行，并新增验收模式结项；现行合法目标文档结构在升级后的验证器下继续有效。

## 为什么要做

2026-07-31 的设计评审（对照 openai/skills 的 define-goal、KKKKhazix 的 leader、本机 grilling skill）结论：当前 skill 的生命周期止步于"交出 /goal 命令"，没有验收环节——宿主的 /goal 评估器只读对话、不跑命令，执行 agent 事实上自己批卷；问询逐题串行成本高；目标文档易膨胀；多个目标共改同一目录时只能靠散文现编约束。8 项改进已由目标所有者逐条确认，其中第 1、3、5、6、7 项的语义已当面澄清并记入下方决策。

## 已确认决策、假设与留白

### 已确认决策（目标所有者 2026-07-31 逐条确认）

1. D1 验收/结项模式：skill 新增验收子模式（调用形如 `/define-goal 验收 docs/goals/某目标.md`）。由未参与执行的新会话 Agent 读目标文档与进度文件，亲自复跑完成契约每条命令，临场派生 2–3 条文档之外的抽查，产出不超过 5 行的人话报告（过没过、干成了什么、未达标项、下一步）；所有者确认后把文档状态翻为"已完成"或"已废弃"并追加结项记录。所有者已明确：验收由模型跑、用户只看报告，全程不需要用户翻文档或跑命令。
2. D2 代拍的板：问询规则改为"承重决策逐题串行问；长尾决策由定义 Agent 代拍默认值"，每条代拍附一句理由与猜错代价，进入确认清单供所有者一次翻牌；问询中"推荐、理由、反论"三要素各限一句话。模板"已确认决策、假设与留白"下新增三级小节"代拍的板（发出前可改判）"。
3. D3 路可换、货不少：模板"工作与取证路径"标题下加固定句——取证与证据要求是硬性的，步骤与顺序是建议；偏离须在进度文件记一句原因，且不得因偏离少交任何证据。所有者已确认此语义。
4. D4 反向验证：goal-patterns.md 防作弊部分新增模式，判据为"这里坏了谁会知道"，答案是"没人"的验收项要求执行者故意制造一次失败、贴出变红输出、还原后贴出变绿输出。按目标选择性使用，不强制每个目标都做。
5. D5 开工回执：模板"执行前复核"新增固定项——动工前写不超过 10 行的"理解的目标、执行顺序、最大风险"回执，回执与本文件冲突时先停再动工。
6. D6 写作纪律：SKILL.md 质量门新增第 11 问（每条已知事实是否支撑某个决策、验收项或停止条件；执行者打开仓库一眼能看到的事实是否已删），并新增"目标简报长度与风险成正比、小目标收在一页内"的校准句。
7. D7 相关目标：模板新增可选二级章节"相关目标"，含三个条目——关联目标与先后顺序、重叠路径与归属、接缝与交接条件；独立目标整节删除。goal-patterns.md 新增"目标间接缝"短节。
8. D8 待裁决清单：模板"停止、升级与续跑"新增固定句——非承重疑问记入进度文件"待裁决"区后跳过继续做不受影响的部分，只有命中停止条件或承重前提冲突才全局停止；goal-patterns.md 停止与续跑部分同步。

### 代拍的板（所有者未逐条裁决，发出前可改判）

以下实现细节由定义 Agent 代拍，执行者按此执行，所有者可在启动前改判任意一条：

- 状态词表：验证器接受 已批准、已完成、已废弃 与 Approved、Completed、Abandoned 共六值；不设"执行中"（执行过程不改契约）。SKILL.md 完成门补一句：定义流程新写的文档状态必须为"已批准"。猜错代价：多余状态删掉即可。
- 误报修复算法：识别二级标题时跳过三反引号围栏内部；扫描占位符时跳过围栏与行内代码。章节正文保留原文——交接章节的 /goal 命令行检测依赖围栏内文本，不得连带丢失。
- 测试位置与清单：仓库根新建 `tests/`（skill 目录保持纯分发内容），fixture 覆盖：现行合法结构（中文、英文各一）、含围栏井号行的合法文档、正文含双尖括号字样的合法文档、"已完成"与"已废弃"状态文档；反例覆盖缺章节、残留占位符、隐藏标记、缺 /goal 命令、非法状态各一。运行命令 `python3 -m unittest discover -s tests`。
- 结项记录格式：验收模式在目标文档末尾追加二级章节"结项记录"（验收日期、结论、逐项核对与抽查摘要、状态翻转记录），格式定义写在 SKILL.md 验收小节；模板不加常驻章节。
- 语言与风格：SKILL.md 与 references 的新增内容用英文、模板新增内容用中文（匹配现状）；SKILL.md frontmatter description 补验收触发词（验收目标、结项、accept or verify a completed goal）。
- 仓库卫生一并做：新增 `.gitignore`（至少含 `__pycache__/`）、删除现存 .pyc、新增仓库根 README（symlink 安装方式、目录布局、验证器与测试的运行命令）。猜错代价：纯增量，不想要删掉即可。
- 验证器对"执行前复核"最少 3 项的检查阈值保持不变，新固定项不推高门槛。

### 假设及猜错的影响
